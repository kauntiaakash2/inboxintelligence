# Learning from workspace simplification

| Concept                         | Concrete implementation                                                              | Alternative and trade-off                                                                                                       | Correctness / industry relevance                                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Progressive disclosure          | Disclosure wraps filters and source diagnostics                                      | Permanently visible forms are easier to discover but compete with reading; keep source identity and active-filter state visible | Native summary keyboard activation, labeled selects, Escape/outside dismissal; common productivity-app pattern          |
| Cognitive load                  | One Inbox / Insights / Settings navigation; no duplicate categories or display forms | More shortcuts may help experts but increase scanning choices; a study must settle the trade-off                                | Test all destinations/legacy URLs and task completion; fewer elements alone does not prove lower mental effort          |
| Information hierarchy           | Sender, subject/preview or category, date; read dot plus weight                      | Badges expose more data but compete with the subject; full detail remains available                                             | Density geometry and row keyboard/reader tests; separate scanning from investigation                                    |
| Navigation and responsive state | Expanded/rail desktop; native mobile drawer                                          | Permanent mobile icon bar is immediately accessible but consumes space and may obscure labels                                   | Test native modal containment, Escape, close/destination, focus restoration and viewport changes                        |
| UI-state persistence            | workspacePreferences exact v1→v2 migration adds sidebarState                         | Separate keys avoid whole-app persistence; broader serialization risks private state                                            | No-write-on-load, invalid schema, reload and storage-error tests; reversible UI preferences are common localStorage use |
| Accessibility                   | Semantic button/summary/select/dialog; visible focus and reduced motion              | Custom div controls require recreating native behavior; native controls still require browser testing                           | Contrast and actual 200% zoom checks supplement semantic tests; screen-reader/user testing remains open                 |

App owns domain and source state; WorkspaceNavigation only receives view/display state and callbacks. Controlled selects use existing category/priority state, so moving their container does not alter filtering. Native details owns transient expansion; React effects install and clean up dismissal listeners. Cleanup matters: stale listeners or unstable callbacks can close/reopen dialogs or misplace focus after rerenders.

The display record serializes a handful of nonsensitive enums as JSON. Parsing returns unknown, not trusted TypeScript: exact runtime validation rejects unexpected keys and unsupported versions. Migration preserves v1 density/layout/default values and adds expanded sidebar state in memory. Explicit save writes v2; reset clears one key. The independent onboarding key and mail/token memory state are untouched. IndexedDB remains a separate future email-retention/privacy decision; this setting does not implement caching or cross-device portability.

Tests caught two practical mistakes: styling a rail without updating inherited main width, and letting a background disclosure consume Escape from a modal. Verify outcomes (usable width, focused control, retained source count), not just implementation classes. Keep before/after screenshots synthetic. Real usability evidence requires comparable tasks, participant observations and errors/time measurements; no participant or onboarding-conversion metrics were collected here.

For an interview, explain the owner problem, the reversible presentation boundary, the disclosure discovery trade-off, the migration and the failure caught by a real browser. Cite measured engineering checks separately from unvalidated product outcomes.
