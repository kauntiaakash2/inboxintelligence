# STRIDE threat model

Scope: static browser client, installed packages, synthetic/Gmail metadata adapters, explicit in-memory Google authorization; future IndexedDB. Assets: private mail, OAuth access, classification integrity, user trust, local metadata and checkpoints. Attacker capabilities: malicious sender, compromised npm package, injected same-origin script, stolen browser profile, shared-device user or hostile network without valid TLS compromise.

| STRIDE                 | Realistic threat                                                                                      | Current mitigation                                                              | Remaining/future work                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Spoofing               | Security-looking subject or spoofed From gains high priority; stolen token impersonates user to Gmail | Rule explanations do not claim authenticity; no real token in automated tests   | Parse sender carefully, consider provider auth evidence; restrict token scope/lifetime and handle revocation               |
| Tampering              | XSS or compromised dependency changes categories/cache/checkpoint                                     | Text-only rendering, runtime boundary validation, lockfile and checks           | CSP, package review, IndexedDB consistency checks; same-origin compromise remains powerful                                 |
| Repudiation            | Correction or sync state changes cannot be explained                                                  | Rule IDs and session event provenance                                           | Versioned local correction/job records; do not call local logs tamperproof                                                 |
| Information disclosure | Malicious HTML, tracking pixels, token persistence, external error logs or profile theft leaks mail   | No HTML/image loads; no secrets/persistence/telemetry; allowlisted event fields | Real-cache retention/delete controls, safe GIS lifecycle, account isolation; device/profile security outside app guarantee |
| Denial of service      | Huge headers/bodies, infinite retries, quota errors, dependency glob amplification                    | Bounded metrics, small fixture; no provider requests                            | Payload limits and aborts in future adapter, bounded concurrency/backoff; development minimatch advisory unresolved        |
| Elevation of privilege | Browser secret or broad Gmail write scope enables unnecessary authority; future tenant bypass         | Explicit read-only OAuth, granted-scope validation, no browser secret           | Review requested/granted scopes, deny cross-tenant server requests and encrypt server credentials if introduced            |

Trust boundaries: mailbox/network JSON is not trusted because it came from Google; Google carries sender-controlled content. TypeScript cannot enforce runtime validity. Browser origin isolation is not encryption against injected scripts or local profile access. Static hosting/CDN serves executable code and must be secured. Third-party package code can execute in build or browser contexts.

Security acceptance before real Gmail: no persistent access tokens, sanitized provider errors, denied/expired auth tests, zero remote email resources, account-switch cancellation, documented retention and scope review. Before SaaS: independent tenant authorization tests, restricted-scope compliance assessment, private incident channel and server credential design.

Phase 2 additionally mitigates stale-callback/source races with attempt counters, source keys, aborts and local data clearing. Reconnect waits for revoke completion/deadline. Remote Google consent after cancellation, SDK compromise, extensions, devtools inspection and same-origin XSS remain risks; no browser-only app can hide a live credential from those actors.

## Phase 3A STRIDE delta

| Threat                                                                            | Mitigation                                                                                                                      | Remaining risk                                                                                          |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Tampering: poisoned preference JSON or invented category/version                  | Strict runtime allowlist, valid enum membership, canonical order and safe defaults; only existing suggested categories accepted | Local preference integrity is not authenticated; a valid malicious choice still changes presentation    |
| Information disclosure: shared browser/profile backup exposes declared role/goals | Optional enum-only record, no account/mail/token fields, explicit clear control, no telemetry                                   | localStorage is readable by same-origin scripts and device users; user-declared choices may be personal |
| Denial of service: malformed/oversized data or denied/quota storage               | 4096-character read cap, parse/storage catch, bounded arrays and tab-local fallback                                             | Browser getItem already allocates its string; this is not a browser-wide resource limit                 |
| Elevation of privilege: personalization triggers mailbox writes or broader access | Pure presentation selectors, existing unchanged classifier/auth/GET-only adapter; fake Gmail preservation tests                 | Same-origin compromise retains the broader browser threat; schema validation does not sandbox code      |

No mailbox persistence or new external trust boundary is introduced. Full email cache/export and multi-user preference identity remain separate future reviews.

## Workspace and proposed capabilities — STRIDE delta

| Boundary / threat                                                          | Current mitigation                                                                                                       | Future gate / remaining risk                                                                                   |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Tampered workspace preferences inject private fields or unsupported layout | Exact four-key/version/enum validation, input cap, safe defaults and key-only reset; original onboarding store untouched | localStorage is not authenticated/encrypted; device/same-origin access remains                                 |
| Stale reading-pane selection exposes another source after disconnect       | Existing session-bound message selection/auth subscription and cleared retained mailbox results                          | Synthetic source-switch/pane tests; no secure-erasure guarantee                                                |
| FULL MIME resource exhaustion / malformed charset                          | FULL retrieval not implemented                                                                                           | Proposed byte/part/depth/time limits, parser tests and honest partial/unsupported states                       |
| HTML XSS, remote pixels, malicious links or attachments                    | Current renderer uses text nodes; no remote content or attachment access                                                 | Separate sanitization/isolation/network policy and adversarial tests before rich reading                       |
| Unintended/duplicate send or repudiated outcome                            | No send scope/form/write transport exists                                                                                | Explicit review/grants, in-flight guard, unknown-outcome handling; no assumed exactly-once provider guarantee  |
| Prompt injection, invented evidence and cross-message exfiltration         | No model or external transfer exists                                                                                     | Separate transfer consent, fixed read set, no tools, schema/evidence validation and held-out attack evaluation |
| AI cost/quota denial and sensitive logs                                    | No paid API or content logger added                                                                                      | Explicit budgets, bounded queues/cancel behavior and scrubbed diagnostics before any provider integration      |

Planned defenses above are not passed implementation tests. Research/user-study notes must use synthetic tasks and anonymous participant IDs, require consent and stay outside Git; no participant data was collected.
