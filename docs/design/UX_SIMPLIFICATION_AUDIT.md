# Workspace simplification audit

Baseline: existing uncommitted inbox-first workspace on feat/clario-design, inspected at 320, 390, 1024 and 1440px and actual Chromium 200% zoom (1440px window → 720 CSS px). Screenshots are synthetic, in output/playwright/simplification-before-*.png. This is an engineering inspection after owner rejection, not a participant study or owner acceptance.

| Location                   | Observed problem                                                                                                 | Change                                                                             | Rationale                                                                                |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Desktop sidebar            | Fixed width; four destinations, eleven category shortcuts, workspace card, privacy promotion and identity footer | Three destinations; explicit collapse to icon rail with named, titled controls     | One primary location per destination, recover reading width                              |
| Overview / Analytics       | Repeated category/sender/priority presentations                                                                  | One Insights destination; preserve both existing URLs and calculations             | Information architecture matches one analytical job                                      |
| Mobile header              | Permanent icon navigation plus source, connection and setup panels                                               | Navigation drawer; persistent source disclosure; compact optional setup invitation | First message previously began near bottom of 900px viewport at 320px                    |
| Source / auth              | Source label, full connection panel, banner and completion panel repeat status                                   | Persistent source summary, contextual connection and diagnostics                   | Preserve honest source information and explicit authorization without occupying the list |
| Inbox controls             | Sidebar categories duplicate category select; display preferences duplicated in Settings and list                | Contextual Filters; Settings owns density and reading layout                       | Progressive disclosure reduces competing choices                                         |
| Message rows               | Category, priority and Gmail label badges beside subject/snippet                                                 | Sender → subject/preview → date; read dot and weight                               | Details retain explanations, categories, priorities and labels                           |
| Reader                     | Empty pane consumes space before selection                                                                       | Split pane only appears after selection; default remains dialog                    | Content space follows an actual reading task                                             |
| Footer / decorative panels | Repeated marketing/privacy copy competes with messages                                                           | Remove application marketing footer and sidebar promotion                          | Public landing page remains the marketing surface                                        |

Protected: onboarding schema/mappings, OAuth, Gmail requests, classification, selectors and analytical calculations. Only the separate display schema migrates v1 → v2 to add sidebarState; migration does not write on load. Mobile drawer state remains transient. Visual acceptance remains the owner's decision.
