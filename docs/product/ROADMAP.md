# Roadmap and evidence gates

Status refers to implementation scope; consult ../quality/VERIFICATION.md for checks actually executed. No dates or user outcomes are promised. Phases 0 and 1 passed their documented local verification gates on 2026-10-31; Phase 2 code is implemented with mocked verification; the owner reported a successful 100/100 live metadata sample and measured attempts/timing; first disconnect/revocation, reconnection and final local disconnect were owner-confirmed; the app was reported absent from Google Account connections when final SDK confirmation was not observed. Live acceptance evidence is owner-reported, with browser/audit limitations retained. Phases 3–10 remain planned.

| Phase | Milestone and dependency                                                  | Exit criteria                                                                                                          | Validation evidence                                                                                   |
| ----- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 0     | Environment and architecture; empty repository                            | Compatible tools; domain contracts, privacy boundaries and ADRs                                                        | ENVIRONMENT.md, ADRs, lockfile; bootstrap implemented                                                 |
| 1     | Mock-data dashboard; requires 0                                           | Four usable views, explanations, combined filters, responsive layout, checks and docs                                  | Logic/component tests, browser artifacts and VERIFICATION.md                                          |
| 2     | Gmail OAuth and latest 100; requires 1 and owner-approved Google setup    | In-memory GIS token, scope validation, bounded metadata retrieval, safe reconnect; initial coverage explicitly partial | Mocked OAuth/API/component/browser checks executed; real consent/import/revocation remains unverified |
| 3     | Initial historical synchronization; requires 2                            | All pages enumerated, every discovered message indexed, checkpoints survive restart, partial failures retry            | Fake multi-page mailboxes, interruption/replay tests and owner-approved import diagnostics            |
| 4     | Incremental synchronization and caching; requires 3                       | IndexedDB schema, history replay, expiring checkpoint fallback, deletion/labels reconcile                              | Transaction/race/404-history tests; repeated real sync consistency checks                             |
| 5     | Pattern analysis and adaptive fetching; requires durable metadata         | Sender statistics, novelty and retrieval-depth policy; complete indexing maintained                                    | Baseline comparison including call counts, bytes and classification quality                           |
| 6     | User corrections and classification refinement; requires 5                | Local correction provenance, rule versioning and drift review                                                          | Correction UI tests; disjoint evaluation and training datasets                                        |
| 7     | Real metrics and optimization; requires 4–6                               | Defined denominators, genuine measurements and error analysis                                                          | Dated runs with source/version/mailbox coverage, precision/recall and call diagnostics                |
| 8     | Deployment and personal production use; requires security review          | Owner-approved static host, headers, revoke/delete controls, recovery and retention checks                             | Staging smoke tests, private personal-use acceptance and budget review                                |
| 9     | Small-user alpha; requires verification feasibility and privacy readiness | Consent, account isolation, feedback channel and operational ownership                                                 | Explicit recruited-user consent, measured retention, incidents and deletion tests                     |
| 10    | Multi-user SaaS feasibility; requires alpha evidence                      | Decide tenant architecture, restricted-scope compliance costs, billing and demand                                      | Documented go/no-go including real economics; no assumed commercialization success                    |

₹0–₹300/month is the personal-use target. Restricted-scope verification or a future server may change feasibility; neither is assumed free. Background push requires additional architecture and approval.
