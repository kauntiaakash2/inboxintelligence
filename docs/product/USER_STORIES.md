# User stories and acceptance criteria

| ID   | Story                                                                      | Acceptance criteria                                                                                                                                                                       | Status                                             |
| ---- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| US1  | As the owner, I want a clear inbox summary so I can choose where to focus. | 96 indexed, 32 unread, 30 high priority; category counts sum to 96; every view identifies mock data.                                                                                      | Implemented; verification record is authoritative. |
| US2  | As an applicant, I want combined search/category/priority controls.        | Case-insensitive trimmed search across name/address/subject/snippet; category and priority apply with AND; interview search returns 6; choosing Orders returns empty; clear restores all. | Implemented                                        |
| US3  | As an explorer, I want to understand a classification.                     | Message opens by keyboard or click; reason, category, rule ID/fallback, confidence caveat and priority score are visible; Escape closes and focus returns.                                | Implemented                                        |
| US4  | As a privacy-conscious user, I want an honest connection status.           | Settings says synthetic repository; Gmail button disabled and phase labeled; no Google authorization request.                                                                             | Implemented                                        |
| US5  | As an analyst, I want reconciliation-friendly summaries.                   | Category/priority sums equal total; sender identities group deterministically; each trend chart describes data and fixture limitations.                                                   | Implemented                                        |
| US6  | As a user, I want recovery when loading fails.                             | Generic actionable error, no raw provider payload; retry starts a fresh local load; empty results suggest clearing filters.                                                               | Implemented                                        |
| US7  | As the owner, I want newest Gmail messages after deliberate consent.       | GIS requests approved read-only scope; token only in memory; at most 100 initial IDs with explicit coverage; metadata adapter validates fields; unauthorized/expired state reconnects.    | Planned Phase 2                                    |
| US8  | As the owner, I want import to survive interruption.                       | Transactional upsert and checkpoint; replay creates no duplicates; partial failures remain visible; checkpoint advances only after safe persistence.                                      | Planned Phases 3–4                                 |
| US9  | As the owner, I want to correct a category.                                | Store previous/new category, time and rule version locally; UI explains the change; evaluation separates learning data from holdout.                                                      | Planned Phase 6                                    |
| US10 | As the owner, I want control over local data.                              | Export with explicit confirmation; delete account cache and token reference; explain Google revocation separately; verify deletion across all stores.                                     | Planned before personal production                 |

All personas are hypotheses. No user interviews or production acceptance results are claimed.
