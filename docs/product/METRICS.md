# Metrics contract

Phase 1 emits only synthetic, session-local events. Displayed counts describe the fixture, never production users or measured Gmail savings. No telemetry is transmitted. Event names are in `src/domain/models.ts`; collection is allowlisted by `MemoryInstrumentation`. Aggregate calculations separate real and synthetic sources; empty denominators yield unavailable, not success.

## Event collection and limitations

Track sync_started, sync_completed, sync_failed, message_indexed, classification_completed, category_corrected, full_body_retrieval_requested, metadata_only_classification. Allowed fields: name, timestamp, source, jobId, optional durationMs. No sender address, subject, body, token or provider error payload. jobId must be opaque and content-free. Session buffer caps at 10,000 and drops oldest entries; it is diagnostics, not a durable ledger. Repeated demo refresh replaces the displayed run rather than inflating inbox totals. Future real jobs require per-message deduplication, persisted summaries and explicit consent before external collection.

Unknown messages trigger a simulated deeper-fetch event; bodies already exist in the bundled fixture. This does not demonstrate reduced body bytes downloaded. Evaluate policy against a measured metadata/full-fetch baseline with identical message coverage before publishing efficiency claims.
